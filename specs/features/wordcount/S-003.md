# Slice S-003: When someone gives `bash scripts/wordcount.sh` more than one argument, they see a usage message that shows both ways to give it text.

<!-- senior-lead-Opus5.5-agent, 2026-10-15. Slice brief from the kit's TEMPLATE-SLICE.md. -->

Feature: [brief](brief.md)
Slice: 3 of wordcount

## Outcome
When someone gives `bash scripts/wordcount.sh` more than one argument, the
usage message shows both ways to give it text: as one quoted argument, and
piped in on standard input (S-002).

## Rules

AC-10  Given more than one argument (`bash scripts/wordcount.sh hello world`),
       when someone runs the command,
       then standard output is empty, standard error is exactly three lines,
       `wordcount: more than one argument given; put the text in quotes`,
       then `usage: bash scripts/wordcount.sh "<text>"`,
       then `   or: <command> | bash scripts/wordcount.sh`,
       and it exits 2.

AC-1 to AC-4 (S-001) and AC-6 to AC-9 (S-002) still hold.

## Retired by this slice
AC-5 (S-001.md): the same error with a two-line message, whose usage line
shows only the argument form. AC-10 replaces it; the first two lines are
unchanged.

## Out of scope
- No argument with a terminal on standard input: it waits for Ctrl-D, as
  `wc` does. Decided in the slice 2 plan (Decisions); not changed here.
- Standard input larger than the Shape's expected 10,000 bytes: not needed
  for this feature (Shape, Expected load).
- Everything in the brief's Out of scope.

## Touch points
`scripts/wordcount.sh`.
