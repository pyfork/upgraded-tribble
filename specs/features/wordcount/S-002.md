# Slice S-002: When someone pipes text into `bash scripts/wordcount.sh` with no argument, they see the number of words in it as a bare number.

<!-- senior-lead-Opus5.5-agent, 2026-10-15. Slice brief from the kit's TEMPLATE-SLICE.md. -->

Feature: [brief](brief.md)
Slice: 2 of wordcount

## Outcome
When someone pipes text into `bash scripts/wordcount.sh` with no argument,
they see the number of words in it, alone on one line, counted by the same
rule as an argument (S-001).

## Rules

AC-6  Given the text `the quick  brown<tab>fox<newline>jumps` on standard
      input, with or without a final newline, and no argument,
      when someone runs `bash scripts/wordcount.sh`,
      then standard output is exactly `5` and a newline, standard error is
      empty, and it exits 0.

AC-7  Given nothing on standard input (`bash scripts/wordcount.sh < /dev/null`),
      or only spaces, tabs and newlines,
      when someone runs the command with no argument,
      then it prints `0` and exits 0.

AC-8  Given standard input whose words hold bytes that are not space, tab or
      newline (`a<CR>b`, `a<form feed>b`, `don't`, `日本語 テキスト`, `*`),
      when someone runs the command with no argument,
      then each of those bytes is part of a word: it prints `1`, `1`, `1`,
      `2` and `1`; a `*` never stands for file names.

AC-9  Given an argument and text on standard input together
      (`echo "a b c" | bash scripts/wordcount.sh "hello world"`),
      when someone runs the command,
      then it prints `2`: the argument is counted and standard input is not
      read.

AC-1 to AC-5 (S-001) still hold. The no-argument usage message of slice 1 is
replaced by AC-6 to AC-8; no rule had locked it.

## Out of scope
- A NUL byte in standard input: bash can't hold one in a variable, and
  neither the brief nor the Shape names it.
- Everything in the brief's Out of scope.

## Touch points
`scripts/wordcount.sh`.
