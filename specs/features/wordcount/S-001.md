# Slice S-001: When someone runs `bash scripts/wordcount.sh "<text>"`, they see the number of words in the text as a bare number.

<!-- senior-lead-Opus5.5-agent, 2026-10-14. Slice brief from the kit's TEMPLATE-SLICE.md. -->

Feature: [brief](brief.md)
Slice: 1 of wordcount

## Outcome
When someone runs `bash scripts/wordcount.sh "<text>"`, they see the number of
words in the text, alone on one line, the same on macOS and Linux.

## Rules

AC-1  Given the text `the quick  brown<tab>fox<newline>jumps`,
      when someone runs `bash scripts/wordcount.sh` with it,
      then standard output is exactly `5` and a newline, standard error is
      empty, and it exits 0.

AC-2  Given text with separators at the start, at the end, or repeated
      (`  hello   world  `),
      when someone runs the command with it,
      then it prints `2`: those separators add no word.

AC-3  Given empty text (`""`) or text of separators only (spaces, tabs,
      newlines),
      when someone runs the command with it,
      then it prints `0` and exits 0.

AC-4  Given text whose words hold bytes that are not space, tab or newline
      (`a<CR>b`, `a<form feed>b`, `don't`, `日本語 テキスト`),
      when someone runs the command with it,
      then each of those bytes is part of a word: it prints `1`, `1`, `1`
      and `2`.

AC-5  Given more than one argument (`bash scripts/wordcount.sh hello world`),
      when someone runs the command,
      then standard output is empty, standard error is exactly two lines,
      `wordcount: more than one argument given; put the text in quotes`, then
      `usage: bash scripts/wordcount.sh "<text>"`, and it exits 2.

Messages follow `scripts/slug.sh` (the brief's "Anything to match"), with
`wordcount` and `text` in place of `slug` and `title`.

## Out of scope
- Standard input: slice 2. In this slice, no argument prints a usage
  message and exits 2, as `slug.sh` does. No rule locks that, since slice 2
  replaces it.
- Everything in the brief's Out of scope.
