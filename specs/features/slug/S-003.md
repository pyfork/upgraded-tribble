# Slice S-003: When someone runs `bash scripts/slug.sh` with `SLUG_CUT=1` and a title whose slug is over 20 characters, they see the slug cut at a word boundary to at most 20 characters.

Feature: [brief](brief.md)
Slice: 3 of slug

## Outcome
When someone runs `bash scripts/slug.sh` with `SLUG_CUT=1` and a title whose
slug is over 20 characters, they see the slug cut at the last word boundary
at or before 20 characters, instead of a slug of any length.

## Rules

AC-12 Given `SLUG_CUT=1` and the title
      `Ten Tips for Writing Better Shell Scripts` (a 41-character slug),
      when someone runs the command with it,
      then it prints `ten-tips-for-writing` and exits 0.

AC-13 Given `SLUG_CUT=1` and the title `How to Name Files Well Today`
      (a 28-character slug whose 20th character is inside a word),
      when someone runs the command with it,
      then it prints `how-to-name-files` and exits 0: the word cut through
      is dropped whole.

AC-14 Given `SLUG_CUT=1` and the title
      `Supercalifragilisticexpialidocious Day` (its first word alone is
      over 20 characters),
      when someone runs the command with it,
      then it prints `supercalifragilistic`, the first 20 characters, and
      exits 0.

AC-15 Given `SLUG_CUT` unset, or set to anything but `1`,
      when someone runs the command with
      `Ten Tips for Writing Better Shell Scripts`,
      then it prints the whole slug
      `ten-tips-for-writing-better-shell-scripts` and exits 0, as before
      this slice.

AC-16 Given `SLUG_CUT=1` and a title whose slug is 20 characters or
      fewer (`Ten Tips for Writing`),
      when someone runs the command with it,
      then it prints the slug unchanged (`ten-tips-for-writing`) and exits 0.

AC-22 Given `SLUG_CUT=1` and the title `Aaaa Bbbb Cccc Dddd Eeee`
      (a 24-character slug whose 20th character is a `-`),
      when someone runs the command with it,
      then it prints `aaaa-bbbb-cccc-dddd` and exits 0: the slug never ends
      in `-`.
      (Added in the plan review round; numbered after the designer's
      AC-17 to AC-21, kept here with the other cut rules.)

AC-17 Given `SLUG_CUT=1` and a title whose slug is cut (each of
      `Ten Tips for Writing Better Shell Scripts`,
      `How to Name Files Well Today` and
      `Supercalifragilisticexpialidocious Day`),
      when someone runs the command with it,
      then standard error is exactly one line:
      `slug: cut to fit 20 characters; use a shorter title to choose the words`.

AC-18 Given `SLUG_CUT=1` and the title
      `Ten Tips for Writing Better Shell Scripts`,
      when someone runs the command with standard output and standard error
      going to one place (a terminal, or `2>&1`),
      then the slug `ten-tips-for-writing` is the first line and AC-17's
      line is the second.

AC-19 Given `SLUG_CUT=1` and a title whose slug is 20 characters or fewer
      (`Ten Tips for Writing`; `Ten Tips, for Writing!`, a 22-character
      title whose slug is exactly 20),
      when someone runs the command with it,
      then standard error is empty.

AC-20 Given `SLUG_CUT` unset, or set to anything but `1` (`0`, `true`),
      and the title `Ten Tips for Writing Better Shell Scripts`,
      when someone runs the command with it,
      then standard error is empty.

AC-21 Given `SLUG_CUT=1` and input that slice 2 rejects (no argument;
      `Hello World` unquoted; `!!!`),
      when someone runs the command with it,
      then standard error is exactly AC-8's, AC-9's or AC-10's lines for
      that input, as without the flag.

Design notes for AC-17 to AC-21:
- The notice says what happened and what to do for other words. Every cut
  gets the same line, whether it dropped whole words (AC-12, AC-13) or
  split one long word (AC-14), so it never claims a word boundary.
- It repeats neither the title (as in slice 2: a title can be 200
  characters or hold control bytes) nor the slug: standard output already
  shows it, or the caller captured it. Fixed text with nothing variable, 71
  characters, so it stays under 80 for any title. No colour codes.
- It names no flag, so the text can stay once the cut is on for everyone.
- It is a notice, not an error: the exit stays 0 and standard output holds
  only the slug, so `$(...)` captures the slug alone. It prints whether or
  not standard error is a terminal; no option silences it (`2>/dev/null`
  does), because the brief names no options.
- The slug comes first (AC-18) so it sits on the line after the command,
  as on every run that cuts nothing; the notice reads as a note on it.
- A `SLUG_CUT` value other than `1` (`true`, a typo) gets no warning: AC-15
  says such a run behaves as before this slice, and the flag is temporary.
- AC-19 to AC-21 already hold on slice 2's script. They keep the notice
  to runs that cut, so it never shows on a good title (AC-11).
- No shared pattern list (`specs/patterns.md`) exists yet; the voice
  follows S-002's design notes.
- States: no loading, retry, disabled or partial state can happen (one
  run, nothing to wait for). Widths, touch, keyboard and screen reader do
  not apply: there is no screen.

## Out of scope
Switching the cut on for everyone and removing `SLUG_CUT` (slice 4).

## Touch points
`scripts/slug.sh`.
