# Slice S-002: When someone runs `bash scripts/slug.sh` without exactly one title that has an ASCII letter or digit, they see an error and a non-zero exit.

     Closes rows 2 and 3 of the tech review of slice 1's build (#36). -->

Feature: [brief](brief.md)
Slice: 2 of slug

## Outcome
When someone runs `bash scripts/slug.sh` without exactly one title that has
an ASCII letter or digit, they see why on standard error, nothing on standard
output, and a non-zero exit, instead of an empty slug.

## Rules

AC-6  Given no argument, or more than one,
      when someone runs `bash scripts/slug.sh`,
      then it prints nothing on standard output and exits 2.

AC-7  Given exactly one title with no ASCII letter or digit (`!!!`, `""`,
      `日本語`),
      when someone runs the command with it,
      then it prints nothing on standard output and exits 1.

<!-- ux-designer-Opus5.5-agent, 2026-10-12. Screen rules: what the person
     reads on standard error. -->

AC-8  Given no argument,
      when someone runs `bash scripts/slug.sh`,
      then standard error is exactly two lines: `slug: no title given`,
      then `usage: bash scripts/slug.sh "<title>"`.

AC-9  Given more than one argument (an unquoted title, as in
      `bash scripts/slug.sh Hello World`, or `bash scripts/slug.sh a b c`),
      when someone runs the command with them,
      then standard error is exactly two lines:
      `slug: more than one argument given; put the title in quotes`,
      then `usage: bash scripts/slug.sh "<title>"`.

AC-10 Given exactly one title with no ASCII letter or digit (`!!!`, `""`,
      `日本語`),
      when someone runs the command with it,
      then standard error is exactly one line:
      `slug: the title needs at least one letter or digit (A-Z, a-z, 0-9)`.

AC-11 Given the title `Hello World!`,
      when someone runs `bash scripts/slug.sh "Hello World!"`,
      then standard error is empty.

Design notes for AC-8 to AC-11:
- Each message names what is wrong and what to do next; the usage line
  shows the one right form. The empty title `""` is one argument, so it
  gets AC-10's message, not AC-8's.
- No message repeats the title back: a title can be 200 characters, span
  lines, or hold terminal control bytes.
- Every line is under 80 characters, so it fits a standard terminal
  without wrapping.
- States: no loading, retry, disabled or partial state can happen (one
  run, nothing to wait for). Widths, touch, keyboard and screen reader do
  not apply: there is no screen.

## Out of scope
Cutting long slugs (slices 3 and 4).

## Touch points
`scripts/slug.sh`.
