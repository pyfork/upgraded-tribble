# Slice S-004: When someone runs `bash scripts/slug.sh` with a title whose slug is over 20 characters, they see the slug cut at a word boundary to at most 20 characters, with no flag to set.

<!-- senior-lead-Opus5.5-agent, 2026-10-12. Slice brief from the kit's TEMPLATE-SLICE.md.
     Switches on the cut that slice 3 built behind SLUG_CUT, and removes the flag. -->

Feature: [brief](brief.md)
Slice: 4 of slug

## Outcome
When someone runs `bash scripts/slug.sh` with a title whose slug is over 20
characters, they see it cut as slice 3 cuts it with `SLUG_CUT=1` (AC-12 to
AC-14, AC-17, AC-18, AC-22), without setting anything. `SLUG_CUT` no longer
changes anything.

## Rules

AC-23 Given `SLUG_CUT` unset and the title
      `Ten Tips for Writing Better Shell Scripts`,
      when someone runs the command with it,
      then it prints `ten-tips-for-writing` and exits 0, with AC-17's
      notice on standard error.

AC-24 Given `SLUG_CUT` set to `0`, `true` or `1`, and the same title,
      when someone runs the command with it,
      then the result is exactly AC-23's: the flag is gone.

AC-25 Given the title `Ten Tips for Writings` (a 21-character slug, one
      over the limit),
      when someone runs the command with it,
      then it prints `ten-tips-for` and exits 0, with AC-17's notice.

AC-26 Given a title where the word cut keeps too little of it,
      when someone runs the command with it,
      then it keeps enough of the title to be useful.

<!-- ux-designer-Opus5.5-agent, 2026-10-12. Screen rules: what the person
     reads on standard output and standard error once the cut is on. -->

AC-27 Given the title `a supercalifragilisticexpialidocious` (the word
      cut keeps under 10 characters, so AC-26's fallback cut applies),
      when someone runs the command with it,
      then standard error is exactly one line, AC-17's:
      `slug: cut to fit 20 characters; use a shorter title to choose the words`.

AC-28 Given `SLUG_CUT` unset, `0` or `1`, and a title whose slug is 20
      characters or fewer (`Ten Tips for Writing`; `Ten Tips, for Writing!`),
      when someone runs the command with it,
      then it prints `ten-tips-for-writing`, exits 0, and standard error
      is empty.

AC-29 Given `SLUG_CUT` unset and the title
      `Ten Tips for Writing Better Shell Scripts`,
      when someone runs the command with standard output and standard error
      going to one place (a terminal, or `2>&1`),
      then the slug `ten-tips-for-writing` is the first line and AC-17's
      line is the second.

Design notes for AC-27 to AC-29:
- AC-17's text stays unchanged. It was written to name no flag, so it reads
  the same now that every run cuts; changing it would break anyone who
  matched it during slice 3.
- The fallback cut (AC-26) gets the same notice, not a second one. AC-17's
  line never claims a word boundary, so it is true for both cuts, and the
  person's next step is the same: a shorter title to choose the words.
- A leftover `SLUG_CUT` gets no warning, on runs that cut (AC-24) or not
  (AC-28). It was a build-time switch, likely to linger in a shell profile;
  a line on every run would be noise about something that no longer
  matters, and it would break AC-28's empty standard error.
- AC-28 keeps the notice to runs that cut, now with no flag set, so a good
  title stays silent (AC-11, AC-19).
- AC-29 is AC-18 without the flag: AC-18 is tied to `SLUG_CUT=1`, and
  AC-24 compares outputs, not their order.
- No new pattern; `specs/patterns.md` still does not exist. No loading,
  retry, disabled or partial state can happen, and widths, touch,
  keyboard and screen reader do not apply: there is no screen.

## Retired by this slice
AC-15 and AC-20 (S-003.md): with `SLUG_CUT` unset or not `1`, the whole
slug and an empty standard error. Slice 4 makes the cut the default, which
is exactly what they ruled out; they were locked in slice 3 as REGRESSION A
so the flag-off path could not break while the cut was being built.

## Out of scope
Any other change to the cut rule or the notice.
