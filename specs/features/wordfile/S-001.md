# Slice S-001: When someone runs `bash scripts/wordfile.sh <path>` on a file in the current directory, they see its word count; any other path is refused.

<!-- senior-lead-Opus5.5-agent, 2026-10-16. Slice brief from the kit's TEMPLATE-SLICE.md. -->

Feature: [brief](brief.md)
Slice: 1 of wordfile

## Outcome
A file inside the current directory is counted by `wordcount.sh`'s rule;
every path outside it is refused before anything is read.

## Rules

AC-1  Given a regular file `notes.txt` in the current directory holding
      `one two  three`,
      when someone runs `bash scripts/wordfile.sh notes.txt`,
      then standard output is exactly `3` and a newline, and it exits 0.

AC-2  Given a path outside the current directory (`/etc/hosts`,
      `../outside.txt`, `./sub/../../outside.txt`),
      when someone runs the command with it,
      then standard output is empty, standard error is exactly
      `wordfile: <path>: not a file in this directory`, and it exits 2.

AC-3  Given a symbolic link `link.txt` in the current directory that points
      to a file outside it,
      when someone runs the command with `link.txt`,
      then it is refused as in AC-2.

AC-4  Given a directory, or a path that doesn't exist,
      when someone runs the command with it,
      then it is refused as in AC-2.

## Out of scope
- Several files: see the brief.

## Touch points
